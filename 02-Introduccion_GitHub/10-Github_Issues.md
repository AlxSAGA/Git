# **GitHub Issues** - Sistema de Seguimiento
Los **Issues** son **tickets o tareas** para organizar y trackear trabajo en un repositorio. Son como **tarjetas virtuales** para bugs, features y tareas.
##### 1. Reportar bugs
- Errores en el código
- Comportamiento inesperado
##### 2. Solicitar features
- Nuevas funcionalidades
- Mejoras al proyecto
##### 3. Organizar trabajo
- Tareas pendientes
- Planificación de proyecto

#### Desde GitHub Web:
1. Ir a repositorio → pestaña "Issues"
2. Click "New issue"
3. Llenar título y descripción
4. Asignar labels, assignees, milestones

**Ejemplo** de un **Issue**
```txt
## Descripción
El login no valida correctamente las contraseñas

## Pasos para reproducir
1. Go to /login
2. Enter wrong password
3. See error

## Comportamiento esperado
Debería mostrar "Invalid password"

## Screenshots
[Insertar imagen si aplica]
```

#### Buenas Prácticas
- Títulos claros y descriptivos
- **Descripción completa** (pasos, expected behavior)
- **Usar templates** para consistencia
- Etiquetar correctamente
- Asignar a personas específicas
- Cerrar issues cuando se resuelven

### Estados de un Issue
**Open** - Sin resolver
**In progress** - Alguien trabajando
**Closed** - Resuelto/completado
**Reopened** - Reabierto (no se resolvió)
