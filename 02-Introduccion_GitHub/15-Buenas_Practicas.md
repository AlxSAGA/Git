**gitigonre**: Siempre agregar este archivo
**Branches**: Crear ramas con objetivos, Cada rama creada tiene que tener un proposito especifico, **( resolver problemas, crear algo nuevo, etc )**
**Nombres descriptivos**: Siempre nombras con objetivo a las ramas con su propocito
**Kebabcase**: Usar convenio para nombrar a las ramas
**Probar el codigo**: Siempre probar el codigo en local, antes de subirlo a produccion
**No trabajar en la rama main**: Evitar trabajar en al rama principal, cada cosa que tengamos que modificar tiene que tener su rama de modificacion
**Utilizar estrategias de branching**: Para fusionar ramas, existen estrategias de todo tipo de formas diferentes de fusiones
**Commits**: Tener una metodologia, deben de tener significado o atomico, por cada cambio importante
**Mantener actualizado**: Actualizar el repositorio
**Tags** Usar tags para **commits**: importantes, los cambios que son significativos se documentan/etiquetan
**Mantener historial limpio**: las ramas locales y remotas no usadas, se eliminan
